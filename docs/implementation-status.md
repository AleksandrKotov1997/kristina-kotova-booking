## Текущий законченный блок

Полный клиентский сценарий Booking по макету: услуга → дата и время →
контакты → заявка. Расписание подтверждено пользователем: Астана, ежедневно
10:00–20:00. Рабочие часы и настройки слотов хранятся в Supabase. Шаг начала
30 минут, окно записи 90 дней; длительность процедуры берётся из активной услуги.

Календарь и слоты доступны с клавиатуры, прошлые/занятые интервалы недоступны.
Цена и длительность не задаются клиентом. Pending сразу занимает время.
Заявки и ручные блокировки защищены общим exclusion constraint в базе;
отмена освобождает интервал. Клиентские имена/телефоны закрыты от публичного
чтения. Повтор после потери ответа сохраняет UUID и возвращает прежнюю заявку.
Старый компонент выбора услуги заменён полноценным BookingFlow.

Проверено: lint, typecheck, production build; тесты Zod, дат и восстановления
после сетевого сбоя/конфликта; SQL-проверка расчёта, пересечений, блокировок,
повтора и приватности с откатом; параллельные запросы через API — 201/409;
production-ошибка и восстановление кнопкой повтора; успешная отправка из
браузера, блокировка pending, сохранение выбора при
возврате, валидация формы и desktop 1024/1280/1440. Тестовые записи удалены.

Следующие продуктовые этапы — Supabase Auth мастера и закрытый кабинет
со списком заявок и обработкой статусов. Они пока не реализованы; ТЗ целиком
не завершено. По запросу пользователя отдельно запланирован Docker-запуск.
UI управления ручными блокировками относится к Admin, сама сущность уже есть.
