## Текущий законченный блок

Admin bookings: /admin показывает настоящую статистику, новые заявки и
ближайшие активные записи; /admin/bookings — полный список с клиентом,
телефоном, услугой, датой, интервалом, статусом и действиями. Есть поиск,
фильтры по статусу и календарной дате, пагинация по 20 строк. Выбор сохраняется
в URL. Обе страницы защищены авторизацией; схема и данные проходят через API.

Мастер подтверждает pending, отменяет pending/confirmed или завершает confirmed.
Обратные переходы недоступны. Окно подтверждения показывает выбранную запись
и последствия; при отправке повторные действия заблокированы. RPC проверяет
роль мастера и изменяет статус под блокировкой строки, сверяя исходный статус.
409 из другой вкладки не теряется при обновлении списка. Триггер защищает
переходы в базе. Отмена освобождает публичный слот, завершение сохраняет
историю занятости. Контакты клиентов закрыты для гостей и других Auth-аккаунтов.

Проверено: 130 тестов, lint, typecheck, production-сборка и Docker;
SQL-права, обзор, фильтры, пагинация и переходы с откатом фикстур;
реальные действия в браузере, конфликт двух вкладок, сохранение фильтра при
перезагрузке, закрытие API/страниц и повторная публичная запись в контейнере.
Тестовые заявки удалены. Ключи не включены в исходники и Docker-образ.

Следующий шаг по ТЗ — мобильная адаптация публичных страниц, записи и кабинета.
После неё — реальные фото, контакты, итоговый прайс и production-размещение.
ТЗ целиком ещё не завершено. blocked_slots предусмотрены и защищают время;
отдельный UI ручных блокировок остаётся допустимым будущим шагом по ТЗ.

### Auth

Supabase Auth: email/пароль, HttpOnly cookies, обновление сессии и выход.
Закрытые страницы и API независимо проверяют getUser() и private.studio_owner.
Разрешён один мастер; роль не берётся из cookie с ID или metadata. Демовход
удалён. Перенос аккаунта Кристине описан в README и не требует изменения env.

### Docker

Production-запуск добавлен отдельным этапом: localhost:3001, существующий
облачный Supabase, Node.js 24.21.0 LTS и pnpm 10.33.0. Многоэтапная сборка
использует frozen lockfile и standalone; сервер работает без root,
с init и healthcheck. Обычный pnpm dev/build/start сохраняет стандартный
режим Next.js. Инструкция запуска и остановки — в README.

.env.local подключается только при запуске; все файлы окружения исключены
из контекста сборки. Локальные ключи проверяются в Git и слоях образа,
в публичные исходники и образ не включаются. Публикация Vercel/Supabase остаётся
этапом production. Для .dockerignore закреплён текстовый режим VS Code.

### Booking

Запись завершена для desktop: услуга → дата и время → контакты → заявка.
Расписание — Астана, ежедневно 10:00–20:00. Шаг начала 30 минут, окно записи
90 дней; длительность берётся из активной услуги. Календарь и слоты доступны
с клавиатуры; прошлые/занятые интервалы недоступны. База защищает заявки и
ручные блокировки от пересечений, отмена освобождает время. Публичное чтение
имён/телефонов закрыто, повтор после потери ответа сохраняет UUID.
