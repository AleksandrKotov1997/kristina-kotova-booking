## Текущий законченный блок

Авторизация мастера: /admin/login по макету с email/паролем, закрытый /admin
с реальной учётной записью и выходом. Supabase Auth проверяет пользователя,
private.studio_owner — право на кабинет. Разрешён один мастер; права не берутся
из cookie с ID или пользовательских metadata. Другой Auth-пользователь не
получает доступ. Старый демовход удалён.

Сессия хранится в HttpOnly cookies; Secure включён в production, SameSite=Lax.
Proxy обновляет cookies для серверной страницы и браузера. Закрытый layout и
API отдельно проверяют доступ; сбои не открывают кабинет. Login/logout принимают
только запросы с сайта, проверяют JSON, схему и размер. Ответы не кэшируются.
Пароль и UUID/email владельца не записаны в исходники, seed или миграции.
Для переноса доступа Кристине достаточно назначить её Auth UUID в базе.

Проверено: lint, typecheck, 78 unit/component-тестов, production-сборка,
Docker, SQL-права с откатом тестовых данных, API-границы и сохранение сессии
после перезагрузки, выход и закрытие кабинета. Публичные API работают без входа. Проверка реальной записи
в контейнере сохраняет атомарные пересечения и повтор заявки.

Следующий шаг — Admin bookings: список заявок, статистика, фильтры,
обработка статусов и ручные блокировки. Мобильная адаптация и реальный контент
с размещением остаются отдельными этапами. ТЗ целиком ещё не завершено.

### Docker

Production-запуск добавлен отдельным этапом: localhost:3001, существующий
облачный Supabase, Node.js 24.21.0 LTS и pnpm 10.33.0. Многоэтапная сборка
использует frozen lockfile и standalone; сервер работает без root,
с init и healthcheck. Обычный pnpm dev/build/start сохраняет стандартный
режим Next.js. Инструкция запуска и остановки — в README.

.env.local подключается только при запуске; все файлы окружения исключены
из контекста сборки. Локальные ключи проверяются в Git и слоях образа,
в публичные исходники и образ не включаются. Публикация Vercel/Supabase остаётся
этапом production. Для .dockerignore закреплён текстовый режим VS Code.

### Booking

Запись завершена для desktop: услуга → дата и время → контакты → заявка.
Расписание — Астана, ежедневно 10:00–20:00. Шаг начала 30 минут, окно записи
90 дней; длительность берётся из активной услуги. Календарь и слоты доступны
с клавиатуры; прошлые/занятые интервалы недоступны. База защищает заявки и
ручные блокировки от пересечений, отмена освобождает время. Публичное чтение
имён/телефонов закрыто, повтор после потери ответа сохраняет UUID.
